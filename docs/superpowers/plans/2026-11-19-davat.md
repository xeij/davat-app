# Davat Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An iPhone app for designing custom invites, sending them over iMessage (live bubble or link), and collecting RSVPs, fundraiser contributions and chat. A small web page serves guests who don't have the app.

**Architecture:** A local Swift package, `DavatKit`, holds the models, fundraiser math, payment links, the canvas renderer and the backend client. Both the app target and the iMessage extension depend on it, and logic tests run with `swift test`. The editor saves invites as layer JSON. Publishing renders a PNG with `ImageRenderer`, and the web page and bubble show that PNG. A `Backend` protocol has two implementations: `SupabaseBackend` (used when `SupabaseURL` is set in Info.plist) and `LocalBackend` (JSON on disk, used until Supabase exists).

**Tech Stack:** Swift 6, SwiftUI, iOS 26 (Liquid Glass, ImagePlayground), XcodeGen, supabase-swift, Supabase (Postgres, RLS, realtime, storage), Vercel (static HTML plus one Node function), vanilla JS with supabase-js from a CDN.

**Spec:** `docs/superpowers/specs/2026-11-19-davat-design.md`

## Global Constraints

- Deployment target iOS 26.0. Bundle ID prefix `com.davat`: app `com.davat.app`, extension `com.davat.app.messages`. App Group `group.com.davat.app`.
- The Xcode project is generated from `project.yml` with `xcodegen generate`. Commit both `project.yml` and the generated `Davat.xcodeproj`.
- Build check: `xcodebuild -project Davat.xcodeproj -scheme Davat -destination 'platform=iOS Simulator,name=iPhone 17 Pro' -quiet build CODE_SIGNING_ALLOWED=NO` must succeed.
- Logic tests: `cd DavatKit && swift test` must pass. DavatKit platforms: `.iOS(.v26), .macOS(.v26)`.
- Copy rules: no em dashes (`—`) anywhere in user-facing strings, the web page or docs. Also no AI-sounding phrasing ("Seamlessly", "Elevate", "Unleash", "✨ magic"). Short, plain and lowercase-casual is fine. The check `! grep -rn "—" Davat DavatKit/Sources DavatMessages web` must exit 0.
- Visual language: SF Pro with `.fontWeight(.thin)` or `.light` for display type. Welcome titles at 56pt or larger, screen titles at 34pt or larger. Buttons use `.glassEffect()` / `.buttonStyle(.glass)` / `.glassProminent`. Transitions use `.spring(duration: 0.4, bounce: 0.2)` and `matchedGeometryEffect` / `.navigationTransition(.zoom)` where they fit.
- Money is stored as integer cents (`Int`). It is never stored as `Double`.
- Git, one branch per task: `git switch -c <branch>`, `bezan <files...> "<message>"`, `git push -u origin <branch>`, `gh pr create --fill`, `gh pr merge --merge`, `git checkout main`, `git pull`. No Claude or Anthropic attribution anywhere.
- Web base URL is the single config value `DavatConfig.webBaseURL` (default `https://davat.vercel.app`). Invite link is `\(webBaseURL)/i/<invite uuid lowercase>`.

## Review Focus

1. Zero going guests, or a fundraiser with the price set to 0: goal and progress must not divide by zero or show NaN. Test in Task 1 (`testZeroGoingGoalIsZeroAndProgressZero`).
2. A Venmo handle typed with `@` or a cashtag typed with `$`: the links must not double the prefix. Test in Task 1 (`testHandlesStripPrefixes`).
3. Opening an invite whose design JSON came from an older or newer app version, with an unknown layer kind: decoding must skip that layer, not fail the whole invite. Test in Task 1 (`testUnknownLayerKindIsSkipped`).
4. A web guest refreshes or comes back later: their earlier RSVP is remembered through a localStorage token, not duplicated. Verified in Task 6 by the RLS upsert on `(invite_id, guest_token)`.
5. A guest without Davat must never see who has paid (spec: visibility). RLS in Task 3: the `responses.paid` column is read through the `invite_public_summary` function, which only exposes totals. Checked by the SQL test in Task 3.

### Task 3: Supabase schema, RLS, storage, web summary view

**Files:**
- Create: `supabase/migrations/0001_init.sql`, `supabase/tests/rls.sql`, `docs/supabase-setup.md` (the steps for the user: create project, run the SQL, enable Apple provider, paste URL/anon key into `Davat/Info.plist` keys `SupabaseURL`/`SupabaseAnonKey` and `web/config.js`)

**Schema:**
- `profiles(id uuid pk references auth.users on delete cascade, display_name text, venmo text, cashtag text)`
- `invites(id uuid pk, host_id uuid references auth.users on delete cascade, title text, starts_at timestamptz, location text, details text, design jsonb, poster_path text, price_cents int, host_pays bool, updated_at timestamptz default now())`. Fundraiser is null when `price_cents` is null.
- `responses(id uuid pk, invite_id uuid references invites on delete cascade, name text check (length(name) between 1 and 60), user_id uuid null, guest_token text null, rsvp text check in ('going','maybe','cant'), paid bool default false, unique(invite_id, guest_token), unique(invite_id, user_id))`
- `messages(id uuid pk, invite_id uuid references invites on delete cascade, name text, user_id uuid null, guest_token text null, body text check (length(body) between 1 and 1000), created_at timestamptz default now())`
- `reports(id uuid pk, invite_id uuid, reason text, created_at timestamptz default now())`

**RLS:** The host has full access to their own invites. Anyone, including `anon`, can `select` an invite by id (the UUID is the secret). `responses`: the host can select all columns and update `paid`. Anon can't select `responses` directly. Anon reads `invite_public_summary(invite_id)`, a `security definer` function returning `{name, rsvp}` rows plus `going_count`, `raised_cents` and `goal_cents`, without per-person paid flags. Anon inserts and updates their own response through `respond(invite_id, guest_token, name, rsvp, paid)` (security definer, upsert on token). `messages`: anyone can select and insert for an invite they know the id of. `delete_me()` deletes `auth.uid()` from `auth.users`. Storage bucket `posters` is public read, and authenticated users write under `<uid>/`. Realtime publication includes `responses` and `messages`.

- [ ] **Step 2:** Validate the syntax. No local Postgres or Supabase is available, so review it carefully. If `npx --yes pgsql-parser` or `npx --yes sql-parser-cst` works, parse with it.
